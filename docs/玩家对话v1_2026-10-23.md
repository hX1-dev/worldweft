# 玩家对话 v1（2026-10-23）

**结论**：规则做主的玩家对话跑通了。NPC 自己决定开不开口、聊几句、为什么收尾；八成的话由规则和模板说，两成交给 DeepSeek。

按《[玩家对话过关标准](玩家对话过关标准.md)》v1.1，最终方案真调三次，自动部分得 85、80、85（满分 85）。平均每段对话用 885 个 token，其中只有约 260 个按全价算，其余命中缓存。另有 15 分待作者盲评，盲评包在 对话盲评包/v1。

## 做了什么

- **过关标准**：[docs/玩家对话过关标准.md](玩家对话过关标准.md)。分人设一致 40、像人 35、省 token 25 三块；第一次真调后收紧为 v1.1。
- **规则层**：`convex/xianxia/playerDialogueLogic.ts`（开口、聊多久、收尾、规则回话、给 AI 的提示词、AI 回话的检查），以及 `convex/xianxia/playerDialoguePersonas.ts`（世界单、10 张人物卡、9 种口气的模板）。全是纯函数，21 条单元测试。
- **试验台**：`godot-taixu-client/tools/player_dialogue_probe.mjs`。从拟人生活主世界（种子 s1）的真实日志里取出 NPC 某一刻的处境，让新来的外门弟子"小陆"按固定剧本，在第 10、12、15 天各找 5 个 NPC 聊一次，共 15 段。
- **打分**：`godot-taixu-client/tools/player_dialogue_score.mjs`。逐项算 A1–C4，B4 留给盲评。

## 谁管什么

| 谁 | 管什么 |
|---|---|
| 规则 | **开不开口**：有事要说、和玩家熟、对新来的人客气才开口；睡着、当值不开口；孤僻、守规矩的人少开口。<br>**能聊几句**：忙着、修炼日、当值、快到就寝、累了就短；话少的人本来就短。<br>**收尾说什么**：照实说他接下来要做的事，例如"我得接着修炼了，回聊！""走了，得去修炼，耽误不得""职责在身，失陪"。<br>**其他**：送不送东西、讲哪件事、记住玩家叫什么、聊过什么、跟他讲过哪些事、问过对谁的看法。 |
| 模板 | 寒暄、回礼、告别、道谢、说在忙什么（含"刚修炼完一轮，歇口气"）、讲听来的事、评人并带上听来的那件事、"上回不是说了嘛"、"就这些了"、推辞、回绝出戏的话。9 种口气，每类 1–3 种说法；同一个人对同一位玩家说过的说法，下次见面不原样再说。 |
| DeepSeek | 只接模板接不住的话，例如"你是个什么样的人""闲下来喜欢做什么""这山里待着习惯吗"。一次回一句，最多表示要收尾；它不做任何动作。 |

给 DeepSeek 的提示词分三段：
1. 所有 NPC 共用的世界单和规矩：只有五处地方、十个人，不许编地方、铺子、价钱，不许答应替玩家做事，山里没处买东西。
2. 这个人的人物卡。
3. 这一刻的处境：身上有几株灵草、累不累、今天和昨天做了什么、见过玩家几回、跟玩家说过哪些事、这段话里他前面说过什么。

前两段不变，命中缓存。

## 一轮一轮改了什么

表里的分都是用最终版检查重打的，各轮可以直接比。

| 轮 | 改了什么 | 自动部分 |
|---|---|---|
| 1 | 第一次真调 | 66（用 v1 原检查是 81） |
| 2 | 世界单放到提示词最前面；处境里写上身上的东西、精神、见过几回；收尾照实说下一件事；说过的说法跨次不重复；NPC 先开口后，玩家问好就回一句；"就这些了"；评人带上听来的事 | 85 |
| 3 | 讲过的事在提示词里标出来；最近的事分今天、昨天；不报价钱，不去数山里有哪些地方 | 75*（实为 85） |
| 4 | 问"你是什么样的人"时，提示 AI 说平常做的事、别背性子；检查认"打过交道的人" | 85、85 |
| 5 | 次数说成"修炼了大半天"，不报"六回"；把他这段话里更早说过的话带进提示词 | 75、85 |
| 6（最终） | 世界单写明山里没处买东西；AI 回话里和前面重了的半句，由规则删掉 | 85、80、85 |

\* 第 3 轮扣分的一句，是卖药弟子说"跟河湾掌柜磨价钱"。这句是真的，日志里他每次卖药都卖给河湾掌柜。那一轮的记录还没存"近 7 天和谁打过交道"，检查认不出来，属于误报。

第一次真调时，v1 的检查一句都没抓到的问题：
- 返山弟子编出"灶房后头有家小摊，卖热汤面"，还说"我带你去认认路"；
- 卖药弟子身上没有灵草，却说"我这儿还有两株"，上一回规则刚替他说过"手上没货了"；
- 卖药弟子刚开口讲完一件事，AI 接着又讲了一遍；
- 第 15 天还问玩家"住得惯么"，因为提示词固定部分里写着"新来的"；
- 八句里差不多有四句以反问收尾。

规则层自己的毛病也在这几轮修掉了：
- 正在修炼却说"回去修炼"，现在说"接着修炼"；闲着说"去修炼"。
- 同一句"回去修炼，先走了"三次见面说两遍。
- 刚讲完白鹿的事，转头又说"没什么新鲜的"。
- 评人时讲过的事，没记成讲过。
- 规则模板里的"我带你认认路""下回给你留着"，规则根本不会去兑现，已删掉。

## token 和速度

| | 第 1 轮 | 最终（缓存是热的） | 最终（缓存刚冷下来） |
|---|---|---|---|
| 每次调用输入 | 约 335 | 约 800 | 约 800 |
| 其中命中缓存 | 10% | 73% | 52% |
| 每次调用输出 | 约 30 | 约 30 | 约 35 |
| 每段对话合计 | 392 | 885 | 890 |
| 每段对话按全价算的部分 | 358 | 约 260 | 447 |
| 中位延迟 | 1.1 秒 | 1.1 秒 | 1.1 秒 |

- 15 段对话共 80 句 NPC 的话，64 句由规则说，16 句交给 DeepSeek，平均每段对话调用约 1.1 次。
- 提示词变长了（多了世界单），但多出来的部分几乎全命中缓存。所以按全价算的部分反而从 358 降到约 260，编造也少了。
- "缓存刚冷下来"指提示词的固定部分刚改过，第一次跑。游戏一直开着时，所有 NPC 共用同一段前缀，缓存一直是热的。
- 估算：如果 80 句全交给 AI，每段对话约 4,300 个 token，约是现在的 5 倍。这个数是按每次约 800 token 推的，没有实测。

## 你的说法，我的判断

你说过"小的决策层，加上用 function API 驱动的固定流程，让 AI 去调用，就能省 token"。这一轮的数据：

- **方向对**：开口、收尾、送东西、讲哪件事都由规则定，AI 只说一句话。
- **省 token 靠的不是 function calling 本身**：
  - 八成的话根本不调 AI；
  - 固定前缀命中缓存，输入的七成多按缓存价算；
  - 每次只回三十来个 token。
- 这一轮没用 function calling：AI 只回 `{"reply","end"}`，动作全在规则里。function calling 每次还要把函数说明带进提示词，反而多花 token。等以后真要让 AI 在几个动作里挑一个（比如"要不要答应这个请求"），再给它一个两三项的小选单就够了。

## 局限

- **自动检查只看字面**：用正则查人名、地方、灵草、承诺、买卖、"今天/昨天"。抓得住这几轮见过的几类编造，抓不住所有的；语气对不对要靠盲评。
- **检查是边跑边收紧的**：每一次收紧都对应一处真问题。第 3 轮修了两处误报：一处把说习惯的"修炼累了"当成"我现在累"，一处不认得打过交道的人；最终轮又修了一处把"你看着有点乏"当成说自己。改动都写进了标准。
- **玩家的话是固定剧本**：说法客气，关键词也是照着剧本配的。真人玩家说得更乱，更多话会落到 AI 头上，token 和出错都会多。上线前要真人试玩。
- **样本小**：5 个 NPC × 3 次 × 3 次运行。AI 的随机性让分数在 80 到 85 之间摆动。
- **还有些小毛病没抓**，盲评包说明里列了，比如：远行采药人说自己"话不多"；重诺弟子像念事实单一样报"昨天修炼了几回，今天也修炼过一回"。
- **还没接进正式游戏**：现在是纯函数加日志试验台。和玩家的往来（说过的说法、讲过的事、问过的人）要存进 Convex，Godot 要有对话界面。
- **测试**：全量 `convex/xianxia` 235 套件、3,050 条测试通过（含新加的 21 条），Convex 和 bridge 两边类型检查也通过。lint 不适用：新文件不在 `tsconfig.godot-bridge.json` 覆盖范围里。
- 代码没有提交。
