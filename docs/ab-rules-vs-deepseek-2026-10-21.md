# 规则组 vs DeepSeek 成对 A/B · 2026-10-21

状态：`round-1 complete / round-2 complete（候选层已修，DeepSeek 臂已复测）`

目的：回答一个被搁置了两个月的问题（LWSE2-D4）：在同一套合法候选上让 DeepSeek 选意图，NPC 是否比规则策略"更活"。指标由作者定：动作熵、聊天率、wait 率、目标成功率。

## 第二轮 · 修候选层（2026-10-22）

第一轮的诊断：采药失败来自候选层，不在策略。作者要求：采药候选加上在途人数和到达时预计剩余量，观察里加上这个来源最近一次的结局，先在规则臂复测 source_missing，再重跑 A/B。

### 真正的失败机制

比"看不见"更具体：每次药圃刷新（每 48–72 tick 一株），6 个左右的 NPC 在 3 个 tick 内先后立下采药目标，只有第一个能采到，其余全部到达即扑空。规则臂每次运行 297–454 次，采药目标成功率只有 14–17%。多数人去并不是因为算错了，而是因为修炼刚做完、正在冷却，采药成了他们唯一的选项，引擎于是照单全收。

### 改了什么

| 层 | 文件 | 内容 |
|---|---|---|
| 事实 | `agentLogic.ts` | `purposeResourceNodes[].outlook`（可选）：在途人数、委托预留数、行程时间、到达时预计剩余量、我上次在此的结局 |
| 计算 | `purposeResourceOutlookLogic.ts`（新） | 预计剩余 = min(容量, 现存 + 到达前的刷新) − 采集中的预留 − 已动身的人 − 委托预留；中文说明文字；"是否争抢"判定 |
| 候选 | `purposeBoundLifeCandidateLogic.ts` | 采药候选（含委托采药）的说明文字后附上 outlook，例如"（另有1人已动身，预计到达时剩0份，你上次来此扑空（12小时前））"。intent、candidateId、sourceRevision 不变 |
| 规则 | `autonomyDecisionTraceLogic.ts` | 预计剩余 < 1 且自己还没在路上：需求分 5、承诺紧迫度 0；规则从不发起这样的行程，没有别的选项时就等待。候选仍在合法集合里，模型能看到并自行选择；模型视图多一个 `resourceOutlook` |
| 优先级 | `decisionPriorityProjectionLogic.ts` | v1 车道里同样降到 L5 `resource_contended_on_arrival`；已在路上的仍是 L3 |
| 模拟世界 | `purposeBoundLifeSoakLogic.ts` | 计算 outlook：已动身 = 别人已立下、尚未开采的采药目标（先立者在前）；委托预留 = 别人已接下、还没动身、还缺货的采集委托；每个 NPC 记住自己在每个来源的最近结局 |
| 发布门 | 同上 | 新增覆盖项 `resourceContentionsAvoided`；"资源稀缺"场景由"途中耗尽"或"事先避开"任一覆盖即可 |

没有接入的：正式游戏的 `runtime/snapshot/agentContext.ts` 还没有填 outlook，所以正式世界的行为与改前完全相同。要接入，需要先决定其他 NPC 的去向对谁可见。

两个顺带发现的问题：

- 只按"先到先得"，接了委托的重诺弟子永远抢不到，委托一次也完成不了。所以加了"委托预留"：散采者把别人未完成的委托视为已占一份。
- 发布门原先要求每次运行至少出现一次途中耗尽。现在规则几乎不会扑空，这一项改为"耗尽或避开"二选一，没有降低别的门槛。

## 第一轮结论

**不支持让 LLM 做逐 tick 的意图选择。** 三个 seed、363 个模型回合，和规则在同一快照上逐回合配对：

| 指标 | DeepSeek | 规则默认 | 差值（95% CI） |
|---|---:|---:|---|
| 选择熵（均匀样本 276） | 1.046 bits | 1.141 bits | −0.096 [−0.163, −0.037] |
| 聊天率（127 回合有 talk 候选） | 40.9%（52/127） | 51.2%（65/127） | −10.2% [−15.7%, −4.7%] |
| wait 率 | 0.6%（2/363） | 0% | — |
| 目标成功率（模型选的 330 个 vs 规则选的 1,685 个） | 86.4% | 92.9% | −6.5% [−10.8%, −2.7%] |

- 与规则默认一致：89.8%（326/363）；均匀样本 91.3%。
- 三个 seed 方向一致：熵、聊天率、目标成功率在每个 seed 上都是 DeepSeek 更低（单 seed 的区间有时碰到 0，合并后全部排除 0）。
- 按事先写下的判据（见文末），落在第一条：把 LLM 从逐 tick 决策里拿掉，保留对话文本与史官。

## 为什么

模型推翻规则默认的 35 次几乎能解释全部差异：

| 推翻方向 | 次数 | 结局 |
|---|---:|---|
| 修炼/聊天 → 去药圃采药 | 25 | 已知结局 19 次，**全部扑空**（`purpose_goal_source_missing`）；另 6 次日志里没挂上终态 |
| 聊天/出行 → 在山门修炼 | 10 | 10 次全部完成 |
| 聊天 → wait | 2 | 都是孤僻的远行采药人拒绝攀谈 |

推翻者：远行采药人 15、药圃弟子 9、返山弟子 8、重诺弟子 2、守静弟子 1。

1. **看不见。** 模型的理由都合人设，例如"行囊缺灵草，趁体力尚可前往灵草丛采集一份，以备修行与日用"。但候选里没有"几个人正赶往药圃、到达时还剩多少"，于是 19 次全部扑空。规则臂同样每次运行有 297–454 个目标死于同一原因（占全部目标 6–10%），这是候选层的缺口，不是策略的缺口。
2. **不记事。** 提示词里没有"上次去扑空了"。远行采药人在 37.5 个游戏日里把同一趟扑空的路走了 15 次。
3. **把性格读得太字面。** "孤僻性格不喜社交，疲劳偏高，暂不主动攀谈，先歇息"。模型因人设拒绝社交，于是聊天率更低。但世界里的 talk 动作总数两臂完全相同（s1/s2/s3：68/88/88），被拒的聊天随后又由规则接上。社交量由冷却和委托决定，不由选择决定。
4. **够不着。** 8.5% 的世界决策会进到 hook（2,298 / 26,906），其余是生存强制、目标续行或只有一个候选。进到 hook 的模型回合里 69% 只有 2 个候选、24% 有 3 个。整条轨迹上两臂几乎一模一样：动作熵 1.658 vs 1.660，目标成功率 91.9% vs 91.8%，引擎空闲 44.6% vs 44.6%。

所以即使换一个更聪明的模型，在当前设计里也改变不了世界多少：NPC 的生活实际是候选生成器写的。

## 怎么跑

- 世界：`purposeBoundLifeSoak` 隔离内存世界（10 个 NPC、5 个地点），3,600 tick = 900 游戏小时 ≈ 37.5 游戏日；不起后端、不碰默认世界、不开监听。
- 两臂同 seed：`ab-20261021:s1`、`s2`、`s3`。规则臂确定性：同 seed 两次运行 `trajectoryDigest` 一致（s1：`stable64:8b8fb444daefb8d3`）。
- 规则臂：每个 hook 决策记录规则默认选择，交回规则执行。
- DeepSeek 臂：每 12 tick 一个均匀采样回合；有社交候选的决策额外加采（`--social-boost`）；其余决策走规则。每个模型回合同时记下规则在同一快照上的默认选择，形成成对样本。熵和 wait 只用均匀样本，聊天率用全部有 talk 候选的回合。
- 公平：模型回合只在最近 120 tick 内出现过 hook 决策的 NPC 之间轮换。
- 提示词：与 2026-08-04 的 c021q7 一小时 soak 完全相同；模型 `deepseek-v4-flash`。
- 指标：动作熵是所选意图种类的香农熵；聊天率是有 talk 候选时选 talk 的比例；wait 率是模型明确回答 wait 的比例；目标成功率是 completed / (completed + failed)，按 decidedBy = llm / rule / engine 分开；95% CI 为 bootstrap 2,000 次（固定种子）。

## 局限

- 一个模型、一个提示词（8 月原版）、一个 10 人 5 地的合成世界、3 个 seed。没有测更强的模型，也没有测带争用信息或记忆的提示词。但提示词只能写进候选和观察里有的东西，缺口在那一层。
- 目标成功率比较的是"模型决定的目标"和"规则决定的目标"，不是严格同快照配对。推翻分析（25 次采药 vs 规则默认的修炼）才是严格配对的证据。
- 6 个模型目标在日志里没有挂上终态（归属到了 engine），不改变方向。

## 运行记录

- 第一次 DeepSeek 运行在第 14–16 回合遇到 DeepSeek 瞬时失败，按原设计连续 3 次失败就熔断，只留下 13 个回合。探测显示 key 和模型都正常。runner 改为：同回合重试 3 次（间隔 3/8/15 秒）、外呼间隔至少 1.5 秒、连续 5 个回合失败才熔断。该日志保留为 `spoiled-*`，不进分析。

## 事先写下的判据（运行前）

- 若模型在成对层的选择熵、聊天率没有以置信区间排除 0 的优势，且目标成功率不高于规则，则把 LLM 从逐 tick 决策里拿掉，只保留对话与史官；
- 若聊天率/熵有优势但目标成功率更低，说明问题在候选信息不足而不在策略，先修候选再复测；
- 两者都有优势才值得继续投入逐 tick 的模型决策。
